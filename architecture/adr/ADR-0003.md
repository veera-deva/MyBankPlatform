# ADR-0003: Stateless JWT Authentication

- **Status:** Accepted
- **Date:** 2026-09-21

> **Note on provenance:** this ADR was referenced by `nfr.md` from early in the project but never actually written to a file. Reconstructed 2026-09-30 from the decision as it was actually built, including the incident noted below.

## Context

- NFR-6 requires authentication with no server-side session state, so the API can scale horizontally without sticky sessions — a hard requirement once this becomes multiple instances behind a load balancer, and later, multiple services.
- Session-based authentication (a server-side session store, e.g. in-memory or Redis-backed, referenced by a cookie) was considered for its simplicity and easy revocation.

## Decision

Authentication is implemented as stateless JWTs. On successful register/login, `JwtService` issues a signed token (HMAC-SHA, via `jjwt`) with the customer's ID as the subject and a short expiry. `JwtAuthenticationFilter` validates the token on every request and populates the Spring Security context. There is no server-side session store.

## Consequences

**Positive**
- Satisfies NFR-6 directly — any instance can validate any token using only the signing secret, with no shared session state.
- Sets up cleanly for the direction taken in [ADR-0004](./ADR-0004.md): a gateway or individual services can validate the same token independently, as long as they share (or can verify against) the signing key, without calling back to an auth service on every request.

**Negative**
- Revocation is hard: a compromised token stays valid until it expires, since there's no server-side session to invalidate. Accepted for v1 given the short expiry window; a denylist or a short-lived-token-plus-refresh-token pattern is a known future improvement, not yet built.
- The signing secret becomes a critical shared credential. Its exposure was in fact a real incident: the secret was originally hard-coded in the tracked `application.yaml` and had to be treated as compromised and rotated, moved to the `JWT_SECRET` environment variable (see the "JWT secret moved to environment variables" commit on 2026-09-21).

## Alternatives Considered

- **Server-side sessions (Spring Session + Redis).** Rejected: reintroduces the shared-state problem NFR-6 exists to avoid, and adds an operational dependency (Redis) earlier than needed.
